# Career 적성검사 웹 연동 계획

## 목적

- `career` 적성/진로심리검사 API는 정기 수집형 DB 적재보다 **사용자 실시간 이용** 성격이 강하다.
- 따라서 1차 목표는 `update` 내부에 수집기를 추가하는 것이 아니라, **사용자가 바로 쓸 수 있는 웹 연동 기준**을 정리하는 것이다.

## 결론

- **문항/결과 API 자체는 Career OpenAPI를 실시간 호출**하는 방향이 맞다.
- `update` 프로젝트는 이 기능의 본체를 직접 서비스하지 않고,
  - 스펙 문서
  - 필요 시 검사 메타 캐시
  - 호출/오류 로그 기준
  만 담당한다.
- 실제 사용자 페이지는 `career` 서비스 웹 영역 또는 별도 PHP 페이지에서 붙인다.

---

## 1. 역할 분리

| 영역 | 책임 |
|---|---|
| `update` | API 스펙 정리, 필요 시 검사 메타 캐시, 운영 기준 문서 |
| 사용자용 웹페이지 | 검사 목록 노출, 문항 진행, 결과 요청, 결과 URL 안내 |
| `robocode-admin/db/` | 호출량/오류/최근 실행 상태 모니터링 |

---

## 2. 웹페이지 최소 기능

### 2-1. 검사 목록

- v1: 직업적성검사, 진로성숙도검사, 직업가치관검사 등 목록 설명 제공
- v2: 직업흥미검사(H) 중학생/고등학생 목록 제공
- 사용자에게 검사명, 대상 학년, 예상 소요시간 표시

### 2-2. 문항 진행

- 검사 선택 후 OpenAPI 문항 조회
- 문항/보기 렌더링
- 답변 누적
- 마지막에 결과 API 호출

### 2-3. 결과 처리

- API 응답의 결과표 URL을 사용자에게 바로 제공
- 필요 시 최근 검사 이력은 **개인식별정보 없이** 최소 로그만 저장

---

## 3. DB 저장 방침

## 저장하지 않는 것

- 개인 답변 원문
- 이름, 학교, 성별 등 개인정보
- 결과 전문

## 저장 가능 항목

| 항목 | 용도 |
|---|---|
| 검사코드/검사명 | 화면 구성용 캐시 |
| 최근 호출 시각 | 운영 확인 |
| 성공/실패 여부 | 장애 확인 |
| 오류 메시지 | 장애 분석 |
| 결과 URL 생성 여부 | 기능 확인 |

즉, **서비스 동작 검증용 운영 로그만 최소 저장**하는 방향이 안전하다.

---

## 4. 구현 우선순위

1. 적성검사 웹페이지 IA/화면 흐름 문서화
2. PHP 기준 단일 검사 실행 페이지 초안 작성
3. OpenAPI 호출 공통 래퍼 정리
4. 호출 성공/실패 로그 저장 여부 결정
5. 필요 시 `robocode-admin/db/` 모니터링 페이지 연결

---

## 5. 권장 첫 구현 단위

### 1차
- v2 `직업흥미검사(H)` 1개 페이지
- 이유:
  - 목록/문항/결과 API 3종이 분리되어 있어 구조 검증이 쉽다.
  - 실제 사용자 흐름을 끝까지 확인하기 좋다.

### 2차
- v1 `직업적성검사` 계열 확장
- 이유:
  - 사용자 요구와 직접 연결된다.

---

## 6. 후속 연계 포인트

- `update` 쪽 후속 작업은 **DB 구축**보다 **운영 로그 기준** 정의가 우선이다.
- `robocode-admin/db/` 쪽 후속 작업은:
  - 최근 검사 API 호출 수
  - 최근 실패 로그
  - 최근 성공 결과 URL 생성 여부
  정도만 먼저 보여주면 충분하다.
